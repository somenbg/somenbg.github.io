Agentic AI engineering assistant

An internal assistant that connects LLM reasoning to infrastructure and enterprise data tools, so engineers can retrieve operational information and inspect internal technical resources.

Working proof of concept

Problem

Operational questions were spread across data stores, repositories, and internal docs. The prototype asks whether an agent with a narrow tool set can shorten that search without widening access past what the engineer should have.

Architecture

  • LangGraph for agent orchestration and FastMCP for tool interfaces.
  • Amazon Bedrock and Google Gemini as model providers.
  • ChromaDB and zvec for retrieval-augmented generation.
  • Amazon S3, Amazon Redshift, and GitHub as enterprise integrations.
  • DynamoDB for session persistence and AWS Secrets Manager for credentials.

Engineering focus

  • Tool orchestration and explicit access boundaries.
  • Stateful conversations that survive a turn.
  • Secure credential handling.
  • Enterprise knowledge retrieval.
  • Agent reliability and observability.

Takeaway

A convincing demo is mostly a model call. A usable internal assistant is the tool boundary: what it can read, where state lives, and how credentials are issued. This system is a working proof of concept, not a production deployment.
