AI research · Automated experimentation

AI-driven automated research framework

An exploration of a research loop in which an LLM proposes changes to a training experiment, the experiment runs, and the result is kept or dropped against a defined metric.

Experimental proof of concept

Problem

ML research spends a lot of time on small, mechanical variations of a training setup. The question is whether a model can propose those variations usefully, inside a budget, without executing untrusted code on shared infrastructure.

Loop

  1. Establish a reproducible baseline.
  2. Generate candidate modifications with an LLM.
  3. Execute the experiments.
  4. Evaluate results against defined metrics.
  5. Retain promising configurations.
  6. Iterate on the next hypothesis.

First evaluation domain

The Kaggle Porto Seguro Safe Driver Prediction dataset.

Research questions

  • Can an LLM guide useful ML experimentation?
  • How should experiments be evaluated and compared?
  • How can the compute budget be controlled?
  • How can execution be sandboxed?
  • What safeguards does AI-generated code need?

Scope

This is experimental research. No production performance improvement is claimed. Related design work on isolating AI-generated workloads is tracked separately under research notes, and is not a completed control plane.
